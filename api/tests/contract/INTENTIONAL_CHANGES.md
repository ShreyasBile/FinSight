# Intentional contract changes

Goldens were recorded from the pre-agent code (commit ef3d045). Every change
below was made on purpose; everything else must stay byte-for-byte equal
(`test_contract.py`).

| Golden | Change | Why |
|---|---|---|
| `compliance_rules.json`, `policy_check.json` | FACE_001 threshold 0.62 → 0.363, `regulation_ref` text | 0.62 was a different face model's scale; FinSight's face module uses SFace, whose validated same-person threshold is 0.363. With 0.62 every genuine match failed the rule. Applied to existing databases by an audited one-time correction (`compliance/router.py::_correct_face_threshold`). |
| `/extract` responses | new optional field `document_identity` | Document Identity agent result (additive; old clients ignore it). |
| `extract_salary_slip_photo.json` | `cleaned_preview` image differs | Page documents (payslips, statements, returns) are no longer run through the ID-card rules in preprocessing: the card rule "taller than wide ⇒ turn 90°" laid a portrait payslip on its side, and the 15%-of-frame contour threshold let a table's ruled box be taken for the page (8 of 18 statement photos were cropped until no transaction row was readable). Pages now need a contour covering half the frame and stay portrait (`preprocess.is_page_doc`). |
| `compliance_rules.json` | `applies_when` on DL_KFS_001, DL_KFS_002, DL_COOL_001, DL_DISB_001, PENAL_001 | The loan-terms rules (Key Facts Statement, cooling-off, fund flow, penal charges) were evaluated during credit assessment, before any offer or loan terms exist, so every application ended in NEEDS_INFO and the supervisor could never recommend approval (found by the real-data evaluation, 2026-10-01). They now apply from the offer stage on (`application.stage`, set by `policy_context.build_context`) and are judged on the Key Facts Statement built with the offer (`agents/tools/kfs.py`). Applied to existing databases by an audited one-time correction (`compliance/router.py::_stage_gate_offer_rules`). A context without `application.stage` (the raw `/compliance/policy/check` API) is evaluated exactly as before. |
| `integrity_pan_genuine.json`, `integrity_salary_photo_genuine.json`, `integrity_pan_copy_move.json` | Genuine synthetic PAN: `risk_tier` HIGH (0.602) → MEDIUM (0.484); in all three, findings of pixel signals that are below their genuine floor are no longer listed in `explanations` | The pixel signals (CNN, ELA, noise, copy-move, photo-region) were scaled on synthetic pages. On real genuine documents they score high (CNN ≥ 0.5 on 80%; ELA / noise / copy-move saturate on many), so 84% of real genuine documents were flagged and 17% rated HIGH (real-data evaluation, 2026-10-01). The fusion now counts a pixel signal only above the score that 95% of genuine real documents of that family reach (`config.yaml: fusion.genuine_floor`, `fusion.calibrated`), chosen on development data only. Weights, confidences, corroboration and tier cut-offs are unchanged. |
| `integrity_pan_genuine.json` | Genuine synthetic PAN: `risk_tier` MEDIUM (0.484) → LOW (0.159), `needs_review` false, no heatmaps | A lone ELA or noise hit — no other signal with evidence — is at least as common on genuine real documents as on forged ones (development data, 2026-10-02: receipts ELA 23 genuine vs 15 forged, noise 12 vs 7; ID images 24 vs 0 and 10 vs 3), because both saturate on ordinary scans. They no longer raise the tier alone; they count in full once another signal backs them (`config.yaml: fusion.needs_corroboration`, `corroboration_min`). On the real test split: genuine receipts flagged 34% → 8%, genuine ID photos 24% → 0.5%. |
| `extract_pan.json` | `pan_number` `ABCPK1234D` → `MCQPD5333A` | The contract run uses the mock provider, which returns a canned PAN whatever the image shows. The PAN number is now checked against the card's own OCR text (`agents/tools/id_crossread.py`): the fixture card prints `MCQPD5333A`, so that is what the response carries. On real-layout cards the reading model alone had the number right on 76% of development cards; with the check, 87%, without changing a correct read. |
| `extract_bank_statement.json` | `total_credits` 540000 → 209610, `total_debits` 499600 → 88898 | Statement totals no longer come from the reading model (the mock's canned figures here; on 60 real-layout statements the local model had no total within 0.5%, and the made-up totals failed the tampering rule "opening + credits − debits = closing" on 16 of 16 genuine development statements). They are the totals the statement prints, else the sums of its rows when the rows run from the opening to the closing balance, else left empty (`agents/tools/transactions.py::apply_summary`). The fixture's rows add up to the new figures. |
| `extract_aadhaar.json`, `extract_salary_slip_photo.json` | `cleaned_preview` image differs | Preprocessing changes from the real-data evaluation: a clean page is not "repaired" as an over-exposed photo, a page is not warped to an inner ruled box, tilts under 0.8° are left alone, and ID cards get a rectangle fallback for the outline (`preprocess.paper_like`, `RECT_FALLBACK`). On real scans the cleanup harmed 31% of pages before and 6% after. |
| `mask_pan.json`, `mask_aadhaar.json` | `masked_image` differs; new optional fields `complete`, `withheld` | The cover's edge is snapped to the real gap before the last four characters and the X glyphs stay inside the box (the first kept character was being clipped: last four readable on 72% of real test documents). A PAN / Aadhaar card whose own number is not found is now withheld (blurred) instead of returned unmasked (`mask.py::_snap_to_gap`, `_withheld`). Both fixture cards still show `XXXXXX333A` / `XXXXXXXX 5784`. |
| `extract_pan.json`, `extract_aadhaar.json` | `cleaned_preview` image differs | The ID-card outline is no longer the first four-sided contour found. Candidates come from regions (brightness, colour, fine print) as well as edges, one score chooses, and below a minimum score no outline is used (`app/card_outline.py`, used by `preprocess._warp_document_robust`). On real phone photos (MIDV-500 test frames) the card is found in 69% of frames instead of 50%, and a wrong outline is used in 2% instead of 9%. The two fixture cards fill the whole image, so nothing is cropped now; before, the picture was warped to a contour just inside the card's edge. |
| all eleven `integrity_*.json` | one more entry in `signals` (`patch_cnn`) and, where it did not run, its "skipped" line in `explanations`; genuine synthetic PAN `risk_score` 0.159 → 0.135 (tier unchanged, LOW) | A new stage-2 signal: a patch-level detector trained on real forged documents - receipts edited by people (Find it again!) and ID images with replaced or repainted fields (SIDTD), development splits only (`tampering/signals/patch_cnn.py`, models in `tampering/models/patch_real_v1/`). Two models per document family, each calibrated on documents it never saw; a document is evidence only when both put it above the score 95% of genuine documents stay under, and the finding names up to three areas for the locator to draw. Alone it gives MEDIUM, never HIGH (`config.yaml: single_signal_confidence.patch_cnn`). On the eleven fixtures it finds nothing (score 0) or does not run (fast-tracked and born-digital PDFs), so no tier changes; the PAN score moves because one more signal with score 0 shares the weighted average. |
