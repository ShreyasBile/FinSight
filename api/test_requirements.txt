# Staging merge of the FinSight backend (requirements.txt) and the new Face
# Detection & Identity Verification module (Ashvin Bari, email 2026-07-09).
#
# Document tampering detection is intentionally excluded, per instruction —
# and not just as a scope choice: that module pins tensorflow==2.12.0, which
# caps Python at 3.11, while this merge targets Python 3.12 (below) with
# tensorflow==2.21.0. The two cannot share one environment. Keep the
# tampering-detection module in its own separate venv permanently.
#
# Recommended Python: 3.12.10 (per the face-matching module's own header)
#
# ── Conflicts resolved during this merge — re-verify before trusting in prod ──
#   - opencv-python (face module) vs opencv-python-headless (finsight): both
#     provide the `cv2` import and cannot safely coexist in one environment.
#     Kept opencv-python-headless since this is a server-side FastAPI backend
#     with no display — switch to opencv-python only if some face-matching
#     dependency turns out to actually need GUI bindings (unlikely for
#     deepface/retina-face/mtcnn).
#   - fastapi / uvicorn / pydantic: took the newer pin from each pair
#     (fastapi 0.115.6→0.116.1, uvicorn 0.34.0→0.35.0, pydantic 2.10.4→2.11.7).
#     pydantic-core's pin below was tied to pydantic 2.10.4 — removed it
#     rather than guess the number matching 2.11.7; let pip resolve it.
#     Re-verify pydantic-settings==2.7.1 still works against pydantic 2.11.7.
#   - numpy: finsight had numpy>=1.26,<3 (a range, not a pin); pinned here to
#     the face module's numpy==2.3.1, which satisfies that range. EasyOCR /
#     torch / scipy / scikit-image below were originally tested against
#     finsight's range, not against numpy 2.x specifically — needs a real
#     install + smoke test, don't trust this blind.
#   - python-dotenv: finsight already pulls 1.2.2 transitively (via
#     pydantic-settings); face module's requirements.txt pinned 1.1.1
#     directly. Kept the newer 1.2.2.
#   - pypdfium2 (finsight) and PyMuPDF (face module) both do PDF handling,
#     via different import names (pypdfium2 / fitz) so they don't collide —
#     just duplicate capability worth consolidating later.
#
# NOT included: transitive dependencies for the face-matching module itself.
# deepface / retina-face / mtcnn / tensorflow pull in a fair number of their
# own (gdown, flask, gunicorn, mediapipe, etc. depending on exact versions).
# Unlike the FinSight transitive section below, these weren't provided as a
# pip freeze — install into a clean venv and run `pip freeze` to capture and
# pin them for real, the same way FinSight's own transitive section was.
# The FinSight transitive section below is also now unverified post-merge —
# several of its direct deps (pydantic, fastapi, uvicorn, numpy) moved
# versions above, which can shift what gets resolved underneath them.
